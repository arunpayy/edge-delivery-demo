Executive & Technical Q&A

Frequently Asked Architecture Questions

When should we choose Edge Delivery Services vs. traditional AEM Sites?

Choose Edge Delivery Services whenever Core Web Vitals (SEO/conversion), authoring speed, and low front-end complexity are top priorities — including marketing sites, campaign microsites, brand hubs, and commerce storefronts. If you also need AEM workflows, DAM governance, or WYSIWYG authoring, pair Edge Delivery with Universal Editor (XWalk) on AEMaaCS.

How does Edge Delivery consistently hit 100/100 Lighthouse scores?

Three deliberate architectural rules: (1) zero framework bundle in the critical path, (2) strict 3-phase loading (Eager for LCP hero only, Lazy for below-the-fold blocks/nav/footer, Delayed at 3s+ for analytics & martech), and (3) automatic image optimization with explicit dimensions to eliminate layout shift (CLS).

Can we integrate dynamic APIs, search, forms, or Adobe Commerce?

Yes. Static semantic content renders immediately at the edge for instant LCP, while interactive blocks fetch Edge JSON sheets (like the Use-Case Explorer above) or external APIs (Adobe Commerce GraphQL, Adobe Target, search indices, or microservices) lazily using IntersectionObserver or on user interaction.

How do we connect this GitHub repository to a live *.aem.page URL?

Install the official AEM Code Sync GitHub App on arunpayy/edge-delivery-demo, choose your content store (DA.live or Google Drive), and preview pages with Sidekick. See the step-by-step guide on the Architecture page or in DEMO_PLAYBOOK.md.
